# 이지스 부위별 Cubism 작업 기록 — 2026-09-05

이 문서는 v1의 실패 및 제작 이력이다. 현재 작업 파일과 검수 결과는 [2026-09-06 v2 기록](aegis-parts-v2-session-2026-09-06.md)을 참조한다.

## 결과와 품질 판정

사용자가 이지스 독립 리깅을 다시 요청했다. 목표는 인기 Live2D 게임 수준의 자연스러운 부위 움직임과 표정이다. **이번 중간본은 이 목표에 도달하지 못했다. 게임에 적용하지 않았다.**

Cubism Editor 5.3.04에서 실제로 새 PSD를 가져와 30개 ArtMesh를 만들고, 화면 왼쪽 손에 독립 워프와 키폼을 작성했다. 편집 원본과 SDK 5.0 MOC3, 2048×2048 아틀라스를 저장했다. 이전에 거부된 모델과 분리 PSD는 사용하지 않았다.

## 저장 위치

프로젝트 기준 `reference/source-assets/overload/live2d-production/aegis/parts-v1/`:

- `aegis-parts-import.psd`: 승인된 원화의 픽셀을 30개 레이어로 추출한 재료 중간본.
- `aegis-parts-import.cmo3`: Editor에서 작성하고 아틀라스까지 저장한 편집 원본.
- `aegis-parts-import.moc3`, `.model3.json`, `.cdi3.json`, `.2048/texture_00.png`: Editor에서 내보낸 검수용 파일.
- `parts.json`, 부위별 PNG, `neutral-reconstruction.png`: 추출 위치와 원본 복원 검사 자료.

이 폴더는 기존 저장소 설정에 따라 Git에서 제외되는 로컬 제작 자료다. 활성 자산 목록에는 등록하지 않았다. `scripts/prepare-aegis-rig-parts.mjs`는 기계적 픽셀 분리 재현용이며 완성 원화 제작 도구가 아니다. 재실행하면 같은 폴더의 PSD/PNG를 다시 작성하므로 수작업 보정 원본을 이 출력 파일에 덮어 보관하지 않는다.

## 실제 작성한 동작

`AEGIS_Hand_L_Flex` 워프는 `Hand_ScreenL` 하나만 포함한다. 워프 분할은 8×12, 베지어 분할은 4×6이다. `ParamAegisHandL`의 -30/0/30 키폼을 Cubism의 흔들림 생성 도구로 작성하고, 위쪽 지점 고정, 가로 1.8, 세로 0, 부드러움 3, 확대·축소 0으로 조정했다. 손목에 가까운 영역보다 손끝 변형이 크다. 이는 손가락별 관절 리깅이 아니다.

기본 Cubism 파라미터 이름이 남아 있어도 이 중간본에서 실제 변형을 가진 파라미터는 왼손 하나뿐이다. 표정, 눈 깜빡임, 시선, 독립 머리카락, 팔 전체, 다리, 상체 호흡 및 물리는 미완료다. 앞선 단일 ArtMesh 실험의 호흡/머리 키폼을 이 모델에 옮기지 않았다.

자동 디포머 생성은 위팔과 일부 머리카락을 하체에 잘못 배정하여 **취소했다**. 잘못된 자동 계층을 저장하지 않았다. 처음 보이던 왼쪽 아래팔 텍스처 누락은 해당 메시 재생성 후 정상 표시되는 것을 확인했다.

## 검수 결과

`scripts/verify-cubism-parts.mjs`와 `tools/cubism-parts-review.html`을 사용했다. 검수 URL은 `http://localhost:4174/tools/cubism-parts-review.html`이다. 이 화면은 마스크가 없고 일반 블렌드인 작업 파일만 지원한다. 렌더 성공은 상용 모델 품질 승인이 아니다.

- 실제 Core ArtMesh 수: 30.
- -30/-15/15/30 검사에서 움직인 메시: `Hand_ScreenL`만.
- 최대 정점 변화: 약 0.00506182 모델 단위, 원화 기준 약 4.37px.
- 중립 복원 정점 오차: 0. UV 범위 오류: 0.
- 검수 페이지의 손 반응 재생·복원, OS 동작 최소화, 브라우저 오류 검사 통과.
- 결과: `qa/cubism-parts-2026-09-05/report.json`, `neutral.png`, `hand-positive.png`.

**시각 검수는 실패다.** 어두운 배경에서 머리카락 조각과 내부 분리 경계가 선처럼 드러난다. PSD 픽셀을 다시 합친 검사에서 차이 0이 나왔다는 사실은, 각 메시가 필터링·블렌딩되는 Cubism 중립 렌더까지 원본과 일치한다는 뜻이 아니다.

## 원화에서 먼저 고쳐야 할 문제

- 레이어는 서로 겹치지 않는 다각형 추출이다. 필터링 경계와 변형 시 생기는 틈을 가릴 겹침 원화가 없다.
- `Seam_Residual`에 약 65,443개의 잔여 픽셀이 흩어져 있다. 별도 부위를 움직이면 이 조각들이 남는다. 각 올바른 부위로 수작업 재배정해야 한다.
- `Hair_Back_ScreenR`은 109픽셀뿐이다. 앞서 처리된 팔/옆머리 마스크가 영역을 차지한 잘못된 분리이며 완성된 뒷머리 부위가 아니다.
- 옆머리와 앞머리 마스크에 피부 또는 의상 일부가 포함되어 있다. 해부학적/선화 경계를 따라 다시 분리해야 한다.
- 눈은 주변 피부를 포함한 하나의 조각이고, 홍채·흰자·속눈썹·눈꺼풀이 별도 분리되지 않았다. 입 역시 내부 원화가 없다.
- 목, 어깨, 팔꿈치, 손목 뒤 의상과 관절면이 없다. 이 상태에 큰 회전이나 물리를 추가하면 품질을 더 악화시킨다.

ImageGen으로 얼굴 피부와 팔 뒤 몸통 보조 원화를 각각 한 번 생성했다. 결과 파일은 `face-underpaint-candidate.png`, `body-underpaint-candidate.png`로 보존했다. 원본 선화 및 비율과 차이가 있고 배경이 실제 알파가 아닌 RGB 체크무늬이므로, **현재 PSD와 게임 텍스처에는 사용하지 않았다.** 원본 파일 식별자는 각각 `exec-5183f01b-e75b-43eb-8ed4-465a41a361f0.png`, `exec-e2caa497-11b8-4867-8ff7-63be02a4463d.png`이다.

다음 제작 단계는 동작 수를 늘리는 것이 아니라 승인 원화의 경계를 정밀하게 재분리하고 숨은 면을 원화와 같은 선화로 보완하는 것이다. 이를 통과한 뒤 얼굴·관절 계층, 각도별 보정, 표정, 호흡, 2차 물리, 클릭별 반응을 작성하고 검수한다. 앞서 완료한 네 전투원의 공통 표시 비율은 유지한다.
