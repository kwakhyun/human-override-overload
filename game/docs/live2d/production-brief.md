# 전투원 Live2D 제작·적용 기준

갱신일: 2026-09-09. 상태: **새 애니메이션 원화 네 명의 Cubism 모델을 로비·정보 화면에 적용**. 현재 결과와 검증 범위는 [애니메이션 리깅 기록](anime-session-2026-09-09.md)이 우선한다. 눈 감김·머리카락·호흡·양팔·코트 움직임을 작성했으며 독립 홍채·입·눈썹 표정은 미구현이다. 아래 2026-09-06 이전 기록은 제작 이력이다.

## 현재 독립 리깅 v2

현재 Editor 작업 원본은 `live2d-production/aegis/parts-v2/aegis-parts-v2.cmo3`다. 소재 경계와 겹침을 보완한 24개 메시 위에 몸통 호흡, 중앙 앞머리, 긴 뒷머리, 화면 왼쪽 팔꿈치의 네 제어를 실제로 작성·출력했다. 왼팔은 아래팔·소매 끝·손을 함께 ±0.5도 회전하며 호흡도 상속한다. 검수 화면에서 부위별 클릭, 반복 반응, 대기 호흡, 원화 비교를 확인할 수 있다.

중립 내부 알파 빈틈 0, 정점 복원 오차 0, 팔꿈치와 호흡의 6개 조합에서 관절 내부 빈틈 0을 확인했다. 이는 제한된 기술 검증이다. 눈·입 표정, 머리 입체 회전, 오른팔과 의상 물리는 미완료이고 세밀한 원화 경계도 더 다듬어야 한다. 아직 게임에는 적용하지 않았다. [v2 상세 기록](aegis-parts-v2-session-2026-09-06.md)과 `tools/cubism-parts-v2-review.html`이 최신 상태다. 아래 단일 메시 및 v1 설명은 앞선 제작 이력이다.

## 앞선 Cubism Editor 단일 메시 실험

Cubism Editor 5.3.04에서 현재 승인 이지스 원화를 새로 가져와 `AEGIS_Breath_Torso`와 `AEGIS_Head_Response` 워프 디포머를 직접 만들었다. `ParamBreath` 0/1과 `ParamAngleZ` -30/0/30 키폼을 편집하고 `.cmo3`를 저장한 뒤 SDK 5.0 대상 `.moc3`를 출력했다. 원화 텍스처는 1024×2048 아틀라스에 회전 없이 100% 배율로 배치했다.

신규 파일은 `reference/source-assets/overload/live2d-production/aegis/aegis-working.*`에 있다. 나머지 세 캐릭터에는 승인 원화의 알파와 픽셀을 보존한 단일 레이어 PSD만 준비했다. 이것은 부위 분리 PSD가 아니다. 폐기된 과거 리그나 자동 절단 PSD를 재사용하지 않았다.

`tools/cubism-editor-review.html`은 신규 MOC3를 실제 Cubism Core로 재생하는 별도 검수 화면이다. 4.8초 대기 호흡, 클릭 후 머리 기울임과 복귀, 수동 키폼 확인, OS 모션 최소화를 제공한다. `scripts/verify-cubism-working.mjs`에서 실제 메시 좌표 변화·하체 고정·중립 복귀·클릭·대기 호흡·모션 최소화·브라우저 오류 없음이 확인됐다. 기록과 캡처는 `qa/cubism-editor-2026-09-05/`에 있다.

**작업본에는 원화 ArtMesh 한 개와 워프 디포머 두 개만 있다.** 눈·입·머리카락·팔다리 분리, 가려진 면 복원, 독립 키폼·물리·표정은 아직 제작하지 못했다. 기본 파라미터 목록에 눈·입 등의 이름이 있어도 해당 변형은 연결되지 않았다. 검수 통과는 두 키폼의 실행 검증이며 고품질 완성 판정이 아니다. 새 Cubism 파일은 게임의 활성 에셋이나 일러스트 렌더러에 적용하지 않았다. 상세 내용은 [Editor 작업 기록](editor-session-2026-09-05.md)을 참조한다.

## 현재 적용된 클릭 반응

2026-09-05 표시 비율 보정: `portraitFraming.js`가 장식·머리카락 외곽 대신 정수리부터 턱까지의 길이를 기준으로 네 캐릭터의 크기와 머리 높이를 맞춘다. 로비·전투원 상세·영입 대화와 정적 복구 화면이 같은 표시 기준을 사용한다. 원본 864×1536 파일은 변경하지 않고 960×1280 공통 표시 프레임에서 원래 종횡비를 유지한다. 원화의 포즈에 따라 하체가 잘리는 위치는 다르다. 이미지와 클릭 영역에 동일한 배율·이동을 적용한다. 사용자는 이 비율 조정을 우선 요청했으며 이지스 독립 리깅은 후속 요청까지 보류했다.

`src/ui/portrait/`의 자체 WebGL 메시가 승인된 원화 네 장을 그대로 사용한다. 로비와 전투원 정보 화면에 머리·상체·왼팔·오른팔·다리 반응, 눈 감김, 국소 호흡, 머리카락 잔동작을 연결했다. 반응의 준비·정점·회복 곡선과 감쇠 스프링은 연속 클릭 시 현재 자세와 속도를 유지한다. 게임/OS 모션 최소화, 비활성 탭/화면의 정지, GPU 자원 해제, WebGL 실패 시 원화 복구를 처리한다.

이는 원화 위의 연속 메시를 작게 변형하는 중간 구현이며, 분리된 눈·입·머리카락 ArtMesh와 디포머를 가진 Cubism 리그가 아니다. 독립 홍채 이동, 숨은 면이 드러나는 큰 회전, 완성된 표정/입 리깅을 구현한 것으로 보고하지 않는다. 사용자 요청의 고품질 Live2D 네 모델 제작은 여전히 남아 있다.

`tools/portrait-motion-review.html`은 개발 서버 전용 비교 검수 화면이다. `scripts/verify-portrait-motion.mjs`는 격리된 브라우저에서 검증하며 결과를 `qa/portrait-motion-2026-09-05/`에 저장한다. 픽셀 변화량은 움직임의 존재만 증명하고 예술적 품질을 보증하지 않는다.

이지스 숨은 면 보완 시안을 내장 ImageGen으로 생성했으나 실제 알파가 없는 RGB 체크무늬 배경과 원본 정렬 오차 때문에 채택하지 않았다. 원화 및 런타임 에셋은 교체하지 않았다. 생성 요청은 얼굴/의상의 가려진 영역 복원, 현재 3/4 포즈와 등록 위치 유지, 실제 투명 배경이었으며 이 조건을 충족하지 못했다.

사용자 요청은 이지스·미카·베스퍼·녹스 전원의 고품질 Live2D 제작과 적용이다. 정적 일러스트를 유지하던 이전 결정은 이 요청에 의해 변경되었다. 다만 현재 발견한 파일은 이 목표를 충족하지 않는다.

사용자가 추가로 확인한 사항: 별도 모델/분리 원본은 없으며, 과거 이지스·미카 파일은 심각한 품질 문제로 제거한 자료다. 네 캐릭터 모두 새로 제작해야 한다. 과거 리그·자동 분리 PSD를 새 제작의 기반으로 재사용하지 않는다. 아래 목록은 실패 자료의 위치를 기록한 감사 이력이다.

## 제작할 원본

각 캐릭터는 현재 얼굴·복장·색상·장비·체형을 유지한다. PSD에는 회전이나 가림 해제 시 드러나는 얼굴·목·피부·의상의 숨은 영역까지 그린다. 단순히 평면 원화를 잘라 나누면 움직일 때 빈틈이 드러나므로 완성된 분리 원화로 취급하지 않는다.

- 얼굴 바탕, 코·귀, 좌우 눈의 흰자·홍채·동공·하이라이트·위/아래 눈꺼풀, 좌우 눈썹, 입술·입안·치아를 분리한다.
- 앞머리·옆머리·뒷머리, 목, 상체·허리, 좌우 상완·팔꿈치·전완·손, 코트/망토의 겹침을 독립 제어한다.
- 이지스: 은발과 코트의 무게감 있는 잔동작. 미카: 트윈테일·링 장비의 탄성 차이. 베스퍼: 짧은 금발과 적색 안감 망토. 녹스: 기존 원화의 액세서리와 의상에 맞는 절제된 반응.
- 프로젝트의 864×1536 표시 프레임과 발밑/중심 기준을 유지한다. 제작용 고해상도 PSD와 표시용 텍스처는 별도로 보관한다.

## 리깅·모션 검수

기본 표준 파라미터: `ParamAngleX/Y/Z`, `ParamBodyAngleX/Y/Z`, `ParamEyeLOpen/ROpen`, `ParamEyeBallX/Y`, `ParamMouthForm`, `ParamMouthOpenY`, `ParamBreath`. 이 이름 목록 자체는 품질 증명이 아니다. 실제 ArtMesh와 디포머 키폼에 연결됐는지 확인해야 한다.

1. 양쪽 눈의 독립 깜빡임과 시선 이동에서 눈꺼풀·홍채가 자연스럽게 가려진다.
2. 머리 X/Y/Z와 상체 회전의 중앙·극값·대각 조합에서 피부, 머리카락, 의상에 틈·중복 얼굴·찢어짐이 없다.
3. 호흡은 상체 내부의 국소 변형으로 보이고 발밑과 전신 위치가 흔들리지 않는다.
4. 머리·상체·팔·다리 터치 반응은 부위별로 구별되며 대기 모션으로 부드럽게 복귀한다.
5. 머리카락/망토/장비 물리는 캐릭터별로 별도 조율한다. 반복 진동이 발산하거나 모션 전환 때 튀지 않는다.
6. 기본 표정과 미소·놀람·집중 표정을 검수한다. 텍스트 대사를 위한 표정 변경만 사용하고 캐릭터 음성 합성은 추가하지 않는다.
7. 대기 20초, 각 터치 반응, 극값 조합을 데스크톱 및 모바일 표시 크기로 직접 캡처해 확인한다.

## 게임 전달 파일

각 캐릭터 폴더에는 `<id>.model3.json`, 실제 `.moc3`, 참조 텍스처, `.physics3.json`, `Idle` 모션, 표정 파일, 선택적으로 표시 정보 `.cdi3.json`이 필요하다. 편집 가능한 `.cmo3`와 PSD는 별도 제작 원본으로 함께 보관한다.

`node scripts/audit-operative-live2d.mjs <모델 묶음 폴더>`로 네 캐릭터 번들의 파일 참조·누락을 확인할 수 있다. 폴더 구조는 `<모델 묶음 폴더>/<id>/<id>.model3.json`이다. 이 검사는 바이너리의 실제 리그 변형 품질이나 SDK 호환성 검사까지 대신하지 않는다.

인자를 생략하면 신규 제작용 `reference/source-assets/overload/live2d-production/`를 검사한다. 현재 이 경로에는 완성 모델이 없으며, 과거 실패 모델을 자동 선택하지 않는다.

## 적용 순서

Windows Computer Use의 `@oai/sky`로 Cubism Editor 5.3.04를 직접 조작했다. 앞서 네이티브 제어 도구가 없다고 기록한 판단은 잘못이었다. 이지스의 두 워프 디포머·키폼·MOC3 출력은 완료하고 실제 Core에서 검증했다. 네 캐릭터의 분리 원화와 독립 리깅은 미완료다. 완성 모델이 준비되면 다음 단계를 진행한다.

1. 실제 모델을 Cubism Core에서 로드하고 버전·메시·파라미터 연결을 검증한다.
2. 로비·전투원 상세·대화 일러스트의 선택된 전투원에 연결한다. 전투원 ID, 잠금 상태, 캐릭터별 반응 대사를 그대로 전달한다.
3. 현재 화면의 모델만 지연 로드하고 전환 시 WebGL 리소스를 해제한다. 비활성 탭과 모션 최소화 설정을 반영한다.
4. 로드 실패 시 현재 승인 원화로 복구한다. 화면 중심과 표시 크기를 유지하고 이중 일러스트가 보이지 않게 한다.
5. 네 모델 모두 시각 검수 후 활성 에셋 레지스트리와 생산 빌드 정책에 등록한다.

공식 참조: [Cubism 임베디드 데이터 출력](https://docs.live2d.com/en/cubism-editor-manual/export-moc3-motion3-files/), [Cubism Web 모델](https://docs.live2d.com/en/cubism-sdk-manual/model-web/).

## AEGIS 부위 리깅 재개 — 2026-09-05

사용자가 독립 리깅을 다시 요청했다. 새 승인 원화에서 추출한 30개 ArtMesh와 왼손 한 부위의 실제 Cubism 키폼을 저장·내보냈다. 파일 무결성 및 손 독립 변형 검사는 통과했지만, 분리 경계와 숨은 면 문제로 시각 품질 검수는 실패했다. **고품질 리깅 및 게임 적용은 미완료다.** 기본 파라미터 이름이나 레이어 수를 완료 근거로 삼지 않는다. 상세 결과와 다음 원화 보완 항목은 [부위별 작업 기록](aegis-parts-session-2026-09-05.md)에 기록했다. 이 항목이 앞선 이지스 작업 보류 문장보다 우선한다.
