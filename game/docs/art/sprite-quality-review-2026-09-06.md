# 전투 스프라이트 품질 검토 — 2026-09-06

검토 기준: 배포 커밋 `d4d802f`. 게임 소스와 원본 이미지는 변경하지 않았다.

## 결론

일괄 해상도 확대보다 **프레임 경계 결함 수정 → 전투원 비율 통일 → 주요 스킬의 화풍 통일 → 외곽 적·보스의 실제 동작 제작** 순서가 효과적이다. 현재 자산은 기능별 구분과 콘텐츠 수량은 갖췄지만, 제작 시기가 다른 자산 사이에 묘사 밀도·신체 비율·움직임의 완성도 차이가 있다.

## 범위와 검증 한계

- manifest에 등록된 전투 아틀라스 41종의 873개 셀에 대해 크기, 투명 경계, 빈 프레임, 완전 동일 프레임을 검사했다. 전체 시트 축소본과 대표 셀 확대본을 육안으로 비교했다. 873개 셀을 각각 확대 검수했다는 의미는 아니다.
- 별도 여러 줄 선언인 동료 모션 시트 3종과 동료 정지 이미지 8종도 비교했다. 따라서 아틀라스 검토 범위는 총 44종이다. DOM 전신 일러스트와 Live2D 리깅은 이번 전투 스프라이트 검토와 별개다.
- 동일 줄에 선언된 PERFORMANCE 변형 28종을 확인했다. 전투원 5종(이지스 두 무기 포함)은 실제 파일 기준 모두 원본 셀 128px, 모바일 셀 96px이다.
- 원본 41종에서는 빈 셀과 완전히 동일한 중복 셀이 없었다. 서로 다른 픽셀이 있다는 사실만으로 동작이 자연스럽다는 결론을 내리지는 않았다.
- 별도 브라우저에서 실제 Phaser 런타임을 직접 마운트해 PC 일반 전투, 1구역 보스, 4구역 보스, 모바일 5구역 화면을 캡처했다. React HUD를 제외한 렌더러 검토용 장면이며, 전체 게임을 모두 클리어한 플레이테스트가 아니다. 사용자 저장 데이터는 수정하지 않았다.
- 초기 4구역 debug 장면은 중간보스 조건 때문에 일반 전투 상태였다. 중간보스 완료를 임시 메모리 상태에 적용하고 실제 보스 진입을 확인한 `runtime-boss04-confirmed.png`만 보스 근거로 사용한다.
- 자동 품질 조절과 헤드리스 브라우저의 영향을 받으므로 이번 캡처의 FPS는 실제 기기 성능 측정치로 사용하지 않는다.

## 유지할 만한 부분

- 전투원은 실제 8방향 8×8 시트가 있고, 방향 전환에 맞춰 해당 행을 선택한다. 한 정면 그림을 회전시키는 구조로 되돌릴 이유가 없다.
- EMP·이지스 방벽, 녹스 스킬, 소버린 출현 게이트, 회복 키트는 형태와 컬러 정체성이 명확하다. 전면 교체보다 다른 효과가 이 기준에 맞추도록 하는 편이 낫다.
- 디펜스 4종 타워의 실루엣 차이는 유용하다. 프레임 경계 결함만으로 시트 전체를 폐기할 필요는 없다.
- 피격·파괴·보스 단계 전환, 수동 스킬의 재생과 게임 판정은 이미 분리되어 있다. 새로운 스프라이트를 적용해도 판정 반경·피해 타이밍·전투 규칙은 유지해야 한다.
- 베스퍼 VFX의 검은 배경은 현재 ADD 합성에서 검은 사각형으로 나타나는 결함과 동일하지 않다. 확인한 문제는 **이웃 프레임의 밝은 조각과 경계**이다. 알파 기반 도구가 24셀 모두 경계 접촉으로 판단한 숫자를 곧바로 24개 결함으로 세면 안 된다.

## 권장 제작 순서와 완료 기준

1. **프레임 정리:** 베스퍼 스킬·디펜스 타워의 혼입/잘림을 수정한다. 검정·회색·밝은 배경과 실제 합성 방식에서 프레임마다 확인한다. 중심점 이동과 플래시 끊김이 없어야 한다.
2. **캐릭터 기준 확정:** 정면·측면·후면에서 네 캐릭터를 같은 화면에 놓고 비례를 맞춘다. 걷기 중 발 기준점과 무기 발사점이 튀지 않아야 한다. 로비 일러스트 비율은 그대로 보존한다.
3. **대표 스킬 정비:** 미카 궁극기와 이지스 검 궁극기부터 완성해 아트 기준으로 삼고 나머지 큰 효과로 확장한다. 피해 영역 안의 적, 위험 예고선, 플레이어가 식별되어야 한다.
4. **외곽 모션 제작:** 4구역 적·중간보스·최종 보스부터 제작한 뒤 5·6구역으로 확장한다. 원화만 풍부해지는 것이 아니라 공격 전후의 실루엣 변화가 보여야 한다.
5. **실기기 검수:** PC 기본/최대 줌, 모바일 기본 전투 크기, 고밀도 전투를 확인한다. 단순 스크린샷 확대와 실제 화면 픽셀 크기를 구분하고, 선택 지역만 로딩하는 현재 방식을 유지한다.

모든 자산의 일괄 2배 업스케일은 권하지 않는다. 실제 모바일 전투원은 카메라 줌으로 매우 작게 보이므로, 텍스처 크기를 키워도 머리카락·무기 세부가 잘 읽히지 않을 수 있다. 실루엣·대비·동작을 먼저 해결하고 큰 보스와 주요 연출에 해상도 예산을 집중하는 편이 효과적이다.
