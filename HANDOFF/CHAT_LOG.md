# TRAIN ME WRONG 개발 채팅 로그

이 문서는 새 Codex가 개발 의도와 변경 이유를 빠르게 복원할 수 있도록 기존 대화를 시간순으로
재구성한 인수인계용 로그입니다. 최근 10개 Codex 턴의 원시 내보내기는
`THREAD_EXPORT_RECENT.json`에 별도로 포함합니다.

## 1. 해커톤 시작과 제출 조건

사용자는 NAN 2026 해커톤 사전 과제로 제출할 고품질 웹 게임 기획을 요청했습니다. 제출물은
브라우저에서 실행되는 빌드와 전체 소스, 30~60초 실제 플레이 영상, 게임 설명 PDF, AI 활용
기술 PDF, 팀 참여 시 역할 PDF였습니다. GitHub Pages 링크, YouTube 링크, 외부 에셋 출처와
라이선스 기록이 필수 조건이었습니다.

기획 후보 이미지까지 만든 뒤 `TRAIN ME WRONG`을 선택했습니다. BGM은 사용자가 Suno AI 등
외부에서 만들고, 캐릭터·맵·효과음은 가능한 한 프로젝트 자체 제작으로 진행하라는 방향이
정해졌습니다.

## 2. 초기 잠입 액션 버전

초기 버전은 스프라이트 캐릭터, 드론, 스테이지별 맵, 총을 쏘는 적, 장비와 능력 선택을 가진
잠입 액션이었습니다. 사용자는 다음 문제를 반복해서 지적했습니다.

- 캐릭터와 드론 움직임이 부자연스러움
- 플레이어 공격력이 약하고 발각되면 바로 실패
- 맵 이미지와 실제 충돌 경로 불일치
- 세 맵이 구조적으로 거의 동일
- 화면에 모두 보이는 작은 맵보다 넓은 맵과 미니맵 필요
- 총성·발각음이 실제 효과음처럼 들려야 함

공격력을 높이고 인간형 적의 발각은 게이지형으로 바꾸며 맵을 확장했지만, 사용자는 게임 자체가
재미없다고 평가하고 타워 디펜스나 뱀파이어 서바이벌류 전환 가능성을 제기했습니다.

## 3. 4구역 지휘 게임 실험

기존 에셋을 버려도 좋으니 품질을 최우선으로 하라는 요청 이후, 4개 구역을 동시에 지켜보는
지휘 게임을 실험했습니다.

- 구역별 서로 다른 영웅
- 한 번에 한 구역만 직접 조작, 나머지는 AI 자동 조작
- 구역 공용 골드와 상점
- 특정 구역이 무너지면 다른 구역으로 적이 침공
- 중반 4구역→2구역, 후반 1구역 합류
- 마지막에 네 영웅이 거대 보스와 협동

하지만 작은 4개 전장을 동시에 보여주는 방식은 액션의 박력과 가독성을 떨어뜨렸고, 관리 피로가
커졌습니다. 사용자는 게임 퀄리티, 도파민, AI 활용 임팩트가 결선 수준에 못 미친다고 평가했습니다.

## 4. 성능 감사와 AI 구조 검토

저사양 MacBook에서 렉과 화면 정지가 발생해 대규모 성능 감사를 수행했습니다.

주요 병목:

- DPR 2 고정 캔버스의 과도한 픽셀 처리
- 매 프레임 배경, 비네트, 스캔라인, 그라디언트 그림자 재생성
- 적마다 Canvas filter와 정렬
- projectile×enemy 전수 충돌
- Web Audio 노이즈 버퍼의 반복 생성
- 실제 표시 크기보다 과도하게 큰 PNG 디코드 메모리

개선:

- 품질 governor와 내부 렌더 해상도 스케일
- 캐시 배경, 그림자, 글로우, 경고 레이어
- 에셋 리사이즈로 런타임 전송·디코드 메모리 대폭 절감
- SFX 노이즈 버퍼 재사용과 voice cap
- 공간 그리드와 충돌 검색 버퍼 재사용

온라인 행동복제용 17→12→5 MLP와 적대적 예측용 14→16→6 predictor도 별도 모듈로 구현되어
테스트가 남아 있습니다. 다만 현재 활성 OVERLOAD 런타임은 이 과거 AI 프로토타입을 핵심 루프로
사용하지 않습니다. 해커톤 AI 임팩트를 다시 강화할 경우 기존 모듈을 무리하게 재연결하기보다
현재 액션 가독성과 성능을 유지하면서 명확한 플레이 원인→AI 결과를 설계해야 합니다.

## 5. 단일 캐릭터 리뉴얼과 ADVERSARIAL 실험

사용자는 4구역 시스템을 전부 제거하고 한 번에 한 캐릭터만 조작하는 게임으로 리뉴얼하라고
요청했습니다. 한때 `TRAIN ME WRONG: ADVERSARIAL`이라는 단일 보스전도 구현했습니다.

핵심 아이디어는 보스가 플레이어의 다음 0.8초 행동을 온라인 모델로 예측하고, 플레이어가 같은
행동을 반복해 보스의 확신을 높인 뒤 반대로 움직여 `MODEL BREAK`를 유도하는 것이었습니다.
기술적으로는 흥미로웠지만 사용자는 재미와 물량전의 시원함을 더 원했습니다.

## 6. 현재 게임 OVERLOAD로 최종 리부트

사용자 요청에 따라 기본 공격은 항상 자동 발사하고 포인터는 조준만 담당하도록 바꿨습니다.
전용 산업 아레나 맵을 제작하고, 대규모 적을 처치해 레벨업하며 무기·기술·동료 중 하나를 선택한
뒤 모든 적을 제거하면 보스전으로 전환하는 서바이버 구조를 만들었습니다.

처음에는 300기였으나 이후 정확히 1,000기로 확대했습니다.

- 시작 즉시 128기 활성
- 고정 시간대에 180/280/412기 대량 증원과 경고
- 동시 논리 적 cap 220
- 전멸 후 2초 보스 전환
- 처치 진행률 48/72/88%에서 오버드라이브
- 후반 자동 마스터 탄막

공격 스킬:

- ARC CASCADE
- ZERO-POINT NOVA
- SKYFALL SUPPORT 공중 폭격
- OMEGA LASER 거대 레이저포
- PULSE, SCATTER, RAIL, ROCKET, ORBIT 계열 무기

보조 시스템:

- Space 대시에 최소 0.46초 무적
- F `4-FRONT RECALL`로 AEGIS ECHO, ROOK, NYX, MOSS를 12초 호출
- 30초 호출 쿨타임
- 줌인 카메라와 우측 하단 미니맵
- Web Audio 절차적 효과음
- 사용자 제공 약 59.9초 BGM 반복 재생

## 7. 보스와 전용 에셋

`THE WRONG ENGINE`은 방사 탄막, 회전 스윕, 지연 폭탄, 확장 링, 단발 돌진, 빠른 연속 돌진을
사용합니다. 돌진을 피해서 보스를 경계에 충돌시키면 3초 동안 코어가 노출되고 실제 피해가 2배가
됩니다.

사용자는 체력 감소에 따른 모습 변화와 광폭화를 요청했습니다.

- 70%: 장갑 전개형 phase 2
- 38%: 코어 멜트다운 phase 3
- 변신 중 잠시 피해 잠금
- 반복 경고와 화면 강조
- 단계별 탄막 밀도, 스윕 수, 링 수, 경고 속도, 연속 돌진 증가

ImageGen으로 보스 phase 2/3 이미지, 보스 패턴 6종 아틀라스, 플레이어 병기 9종 아틀라스를
제작했습니다. 크로마키 원본은 `game/reference/source-assets/`에 보존하고 런타임 PNG는
`game/public/assets/survivor/`에 최적화해 저장했습니다. 모든 프롬프트와 출처는
`game/CREDITS.md`에 기록했습니다.

## 8. BGM 적용

사용자가 제공한 `300 드론 생존전.mp3`를
`game/public/assets/audio/overload-main-theme.mp3`로 적용했습니다. 시작 버튼의 사용자 제스처로
재생하며 게임 중 반복되고, 전체 사운드 토글과 연동됩니다. 해당 파일은 사용자 제공 외부 제작
음원으로 CREDITS에 기록되어 있습니다.

## 9. VFX·애니메이션 감사

사용자는 메이플스토리와 던전앤파이터 같은 2D 게임의 캐릭터·보스 모션과 스킬 이펙트 제작
방식을 질문했습니다. 검토 결론은 프레임 도트/래스터, 레이어 합성, 대형 개체의 본·메시
애니메이션, 별도 VFX와 카메라 연출을 섞는 하이브리드 파이프라인이었습니다.

코드 감사에서 VFX보다 먼저 고쳐야 할 P0가 확인되었습니다.

- 레벨업 모달이 연속으로 나타나 타격 연출을 덮음
- 세 번째 동료 선택지가 약함
- 대규모 공격에서 렉
- 보스가 패턴 전에 사망
- 보스 텔레그래프와 실제 판정 불일치
- HUD 글자가 지나치게 작음
- 포인터와 에임이 카메라 가장자리에서 어긋남

- 초과 레벨은 공격력·공속·체력 영구 코어 보너스

동료:

애니메이션:

- 플레이어 5×3: 이동, 사격 예비/발사/반동/회복, 대시, 피격

성능:

- 공간 그리드 버킷과 nearby scratch 재사용
- 로켓 직격과 splash 중첩 검색 안전화
- 대량 사망 시 단일 fade/scale LOD
- 일반 적 체력바 예산 제한

## 12. 새 세션이 알아야 할 핵심

- `game/AGENTS.md`의 durable decisions가 현재 사용자 의도입니다.
- 과거 4구역, 잠입, ADVERSARIAL 루프를 현재 App에 다시 연결하면 안 됩니다.
- 기존 사용자 소유 변경과 원본 에셋을 보존해야 합니다.
- 외부 에셋을 추가하면 출처와 라이선스를 CREDITS 및 AI 기술 문서에 기록해야 합니다.
- Sites 공개 배포는 사용자 명시 승인 후에만 진행합니다.
- 해커톤 제출에는 아직 30~60초 실제 플레이 영상, 게임 설명 PDF, AI 활용 기술 PDF가 필요할
  수 있으므로 제출 체크리스트를 다시 확인해야 합니다.
- 현재 게임의 가장 큰 전략적 리스크는 게임 내 AI 활용이 과거 predictor/behavior-cloning
  프로토타입보다 약하게 보일 수 있다는 점입니다. 다시 강화할 때는 성능과 현재 액션 루프를
  훼손하지 않고 심사 영상에서 즉시 이해되는 원인→학습→결과 구조를 우선해야 합니다.
